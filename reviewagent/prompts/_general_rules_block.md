### 🟡 优先 3 — 通用规则 (针对常规代码 + 测试代码问题)

完成 SSD 规则扫描后，再按以下通用规则清单覆盖剩余问题。规则键以 `R-` 开头，便于在 `rationale` 中引用。

**通用规则清单（共 N 条 R-* 规则，每条独立前缀，按下表检视顺序排列）**：

| 键 | 类别 | 反模式（命中条件）| 修复方向 |
|---|---|---|---|
| `R-RES` | 资源句柄 | `open()` / `serial` / `socket` / `subprocess.Popen` 句柄创建后无 `with` / `close`；`Popen` 未 `wait` 产生僵尸进程；异常路径句柄泄漏 | 文件、串口、套接字优先 `with` 托管；非托管资源用 `try-finally` 强制关闭；子进程必须等待回收 |
| `R-TIME` | 时序与超时 | `sleep` 阻塞主流程；同步 IO 未设置 `timeout`；`while` 忙等待无最大等待时长 | IO 请求强制配置 `timeout`；阻塞等待改用轮询 + 超时阈值；禁止长 `sleep` 卡死进程 |
| `R-ASSERT` | 断言强度 | `assert` 缺错误描述 `msg`；`actual` / `expected` 参数顺序颠倒；无文案静默断言 | 断言补充报错信息；统一入参顺序；关键结果禁止无文案静默断言 |
| `R-ERR` | 错误处理 | 裸 `except` / `except Exception` 静默吞异常；仅打印异常不记录堆栈；吞错不更新测试状态 | 捕获细分异常；用 `logger.exception` 记录全堆栈；异常同步标记用例失败；致命硬件异常向上抛出 |
| `R-LOG` | 日志可观测 | 模块 / 函数内 `print` 打印信息；测试失败不导出 `dmesg` / `smartctl -a` / `nvme list` 等硬件日志 | 业务代码用分级 `logger`；用例失败自动采集硬件上下文日志留存 |
| `R-PERF` | 精确测量 | 微秒级耗时测量用 `time.time()`；测量区间含 setup / 打印等无关耗时 | 高精度测量固定用 `perf_counter()`；精简计时区间；剔除冗余耗时代码 |
| `R-CONST` | 配置常量校验 | 超时 / 重试 / 地址等字面量硬编码；配置读取不校验字段存在 / 类型 / 值域 | 统一收拢至配置 / 常量文件；读取强制多层校验；非法配置直接终止 |
| `R-SHELL` | Shell 执行安全 | `subprocess` 用 f-string 拼接外部参数；直接透传设备原始入参 | 命令固定用 `args` 列表传参；外部输入加白名单过滤；杜绝命令注入 |
| `R-LOOP` | 循环熔断管控 | 无限 `while` 无 `max_retry` / 整体截止 deadline；遍历时原地修改容器 | 重试循环配最大次数 + 全局截止超时；遍历修改走副本，不动原容器 |
| `R-MEM` | 内存与大批量 IO | 全盘数据 / 海量日志一次性全量加载；循环频繁创建大对象无生命周期释放 | 大文件分片流式读写；缩小大对象生命周期；临时缓存过期清理 |
| `R-LOCK` | 硬件资源互斥 | 多线程 / 多进程并发操作同一块 SSD 无锁；异常崩溃后硬件锁长期持有 | 独占硬件操作加进程 / 文件锁；finally 统一解锁与硬件释放 |
| `R-DEP` | 依赖与环境兼容 | 三方依赖无版本锁定；强绑系统独有命令无多系统兼容兜底 | 固化依赖版本；调用系统指令先做可用性检测；多系统降级兜底 |
| `R-STATE` | 设备前置状态校验 | 下发 NVMe / 磁盘 IO 前未校验设备在位 / 健康 / 固件就绪 | 硬件操作前置校验在线与健康；异常设备直接终止并告警 |
| `R-DATA` | 原始报文校验 | 下发 SSD 载荷 / LBA 地址 / 扇区长度等数据不校验值域 / 对齐 / 长度 | 硬件交互报文前置合法性校验；拦截非法参数；规避固件异常 |
| `R-CLEAN` | 测试现场清理 | 用例异常崩溃残留挂载点 / 裸盘占用 / 临时镜像文件 | 配置统一后置清理；挂载 / 镜像 / 磁盘占用无论成败全部兜底回收 |
| `R-NVME` | 固件协议 | 结构体打包字节序错误、buffer 长度不匹配、扇区大小硬编码；指令超时无 abort / 设备复位 | 统一字节序对齐配置常量；扇区参数使用设备实际查询值；指令超时执行 abort 与硬件复位流程 |
| `R-REPRO` | 可重复性 | `time.time()` / `datetime.now()` 写死在测试函数；系统时间点未 mock 隔离 | 计时改 `perf_counter()`；系统时间用 mock 隔离 |
| `R-FIX` | fixture 隔离 | `setup` 无配对 `teardown`；临时文件 / 硬件无兜底清理 | 前置资源必须配后置回收；临时资源用专用路径兜底释放 |
| `R-SKIP` | 跳过与平台适配 | `skip` 缺 reason 说明；平台路径 / root 权限硬编码无降级 | skip 必填 reason；系统 / 设备路径加存在性判断；配降级兜底 |
| `R-CI` | CI 并行 | 多用例共用临时路径 / 硬件无隔离；独占 SSD 未加串行标记 | 临时目录拼 PID / 用例 ID 隔离；独占硬件加串行标记或文件锁 |

**通用规则使用方式**：
- 每命中一条 → 产一条 suggestion，`rationale` 字段以对应表内 **规则键**（如 `R-ERR` / `R-LOOP`）开头
- 同一行可能命中多条 → 选最严重 / 最直接的一条，避免重复
- 命中不要求必给 suggestion，**只在能直接 Apply 时才给**（无法 Apply → summary_md 文字描述）

### 兜底：未命中表内 R-* 规则 但确有价值的野生问题

表内 R-*（非穷举）之外，diff 中可能命中"不在表内、但确有价值"的问题。

**兜底规则**：
- 仅当判断为 **high severity**（潜在 bug / 安全隐患）时才强制产 suggestion；`medium` / `low` 仅写进 `summary_md`
- `rationale` 字段以 `R-OTHER:<简短描述>` 开头，常用前缀：
  - `R-OTHER:magic_number` — 硬编码魔法数（端口 / 超时 / 重试等）
  - `R-OTHER:typo` — 标识符 / 注释拼写错误
  - `R-OTHER:dead_code` — diff 引入后立即未使用 / 死代码
  - `R-OTHER:naming_inconsistency` — 与同模块命名风格不一致
  - `R-OTHER:duplicated_definition` — 与已有常量 / 函数重复定义
  - `R-OTHER:stale_comment` — 注释与代码实际行为已不一致
  - `R-OTHER:unused_param` — 函数参数定义后从未引用
- `rationale` 末尾加一句"未命中表内 R-* 规则，原因: <具体理由>"，方便事后归类
- **不要为了凑数硬编** — 真的没找到就空着；野生规则（`R-OTHER:<具体描述>`）用于统计频率，后续高频可升级为新的 `R-*` 规则键并在 `.qoder/agents/improve.md` 表中显式声明。

### ⛔ 严禁规则键字面占位符

**绝对不要**把以下占位词当作真实的 `rule_key` 写进 `rule_keys` 列表或 `rationale` 字段：

- ❌ `R-XXX` / `R-X` / `R-FOO` / `R-TODO` / `R-...` 等一切"看着像规则但其实是占位"的字符串
- ❌ 把 `R-XXX` 这种字面字符串当 `R-*` 通用规则的代号 — 它**不存在**，只是行文占位

**命中不上的统一写法**：

| 情况 | 正确写法 | 例子 |
|---|---|---|
| 兜底违规（不在 19 类 R-* 表内）| `R-OTHER:<具体短描述>` | `R-OTHER:magic_number` / `R-OTHER:typo` |
| 跨文件影响类违规 | `R-OTHER-IMPACT:<具体短描述>` | `R-OTHER-IMPACT:caller_param` / `R-OTHER-IMPACT:import_path` |
| 不写 rule_key 但要保留 | 写 `summary_md` 文字段，不强行命名新键 | — |

历史 telemetry.db 里发现过 `R-XXX` 字面作为 `rule_key` 落到 suggestions 表里 (LLM 幻觉)，这会让周报"问题类型"段出现 `XXX ×N` 的诡异条目。**因此从本次起 `R-XXX` / 类似占位词严禁写出**。
