### ⛔ 检视边界 — 先决定「不报什么」，再按正向规则扫描

本节的判定**先于**之后所有正向规则。正向规则回答「能发现什么」，本节回答
「发现了也不该报什么」。目标：只报**有影响**的问题，宁少勿滥。

**场景前提（本节全部裁剪的依据）**：本次检视的对象是**仓库内部自动化测试代码**
（`testcase/` / `testlib/` / `test_components/` / 测试 fixture），运行在**内网测试台**
上、由流水线调度，既不对外提供服务，也不处理外部用户输入。
因此「面向生产服务的安全加固」类检查在本场景**没有可执行的后果**，一律不报。

**判定顺序（强制）**
1. 候选问题先过本节「不报清单」→ 命中即**丢弃**：不产 suggestion，也不改写进
   `summary_md` 凑数；但**命中下方「强制例外」的候选先跳过本清单**，直接照常产出；
2. 未被丢弃的，再按「跨文件影响 → 仓库自定义规则 → 通用 R-*」顺序产出；
3. 本节只裁剪**通用 / 风格层**；下方「强制例外」优先级高于本节。

#### 不报清单

| 类别 | 不报的情况 | 唯一例外（仍要报） |
|---|---|---|
| 安全类 | 命令 / SQL 注入、`shell=True` 拼接外部入参、明文凭据（口令 / token / 私钥写死在代码里）、越权、路径穿越、不安全反序列化（`pickle` / `eval`）、弱哈希 / 非密码学随机、敏感信息（口令 / 密钥）打到日志、文件权限过宽 | ——（本场景无对外攻击面，无例外） |
| 依赖与环境 | 三方依赖未锁定版本；强绑系统独有命令无多系统兼容兜底（CI 镜像已固定依赖与系统） | 可选依赖 `import` 失败导致用例无法执行；环境不兼容导致整批用例挂掉 |
| 纯文本 | docstring / 注释 / README 的措辞、拼写、标点、格式、翻译 | 注释参与执行（doctest、`# noqa`、`# type: ignore`、`# pragma`、shebang、编码声明）；或注释与代码行为**矛盾且会误导**（`R-OTHER:stale_comment`，low） |
| 描述类 | MR 标题 / 描述 / summary 文案本身；「描述可以更详细」 | 描述与 diff 实际行为不一致，会误导 reviewer |
| 非代码强相关 | 空行与换行、引号风格、import 排序、括号换行、命名口味 | 该写法导致可验证的性能 / 正确性 / 兼容性问题 |
| 等价改写 | 行为完全一致的重写（手写累加→`sum()`、`if/else`→三元、提前 return 等） | 改写带来可测收益（已造成性能或维护缺陷），或仓库规则明确要求 |
| 影响不大 | 泛化的「建议补测试」「建议加类型注解」「建议拆函数」「建议加日志」，未锚定本 diff 的具体行为变化 | 本 diff 新增分支 / 异常路径且完全无覆盖；或类型错误会导致运行时失败 |
| 重复 | 同一根因的多处表现、同一行命中多条规则 | 只保留最严重 / 最可 Apply 的一处；不同行、不同文件的独立问题不受限 |

> **安全类不报 ≠ 硬件数据类不报**：下发 SSD 载荷 / LBA 地址 / 扇区长度的值域与对齐校验
> 属于 `R-DATA` / `R-NVME`，会造成硬件损坏或数据错误，**仍要照常报**（见「强制例外」）。

#### 强制例外（本节不生效，必须照常报）

- **数据损坏、硬件损坏或不可恢复的设备状态**；
- 用例假通过 / 假失败、断言被吞、资源泄漏、僵尸进程、并发无隔离；
- NVMe / 协议 / 字节序 / 扇区长度等硬件交互错误；
- 跨文件 caller / 引用方失配（`R-OTHER-IMPACT:*`）；
- **注释与代码行为矛盾且会误导**（`R-OTHER:stale_comment`，low）——例如注释声称返回
  布尔标识、实际返回状态字符串，或注释描述的调用前提与实现不符：会把调用方直接带偏，
  必须照常产出，不得按「纯文本」丢弃；
- **仓库自定义规则明确要求的条目**——例如仓库规则要求测试函数必须有 docstring、
  必须带 allure 字段、必须保留加载标记：即使它本质是「文本 / 元数据」，也按仓库
  规则照常产出 suggestion，severity 按规则文件标注。

#### low 级自检（逐条问，答不上就丢弃）

1. 不改它，具体会出什么后果？（不是「可读性更好」，而是可观察的后果）
2. 这个后果能在本次 diff 内验证吗？

两问都答不上 → 丢弃；只有一处能答上 → 只在能答上的那一处报。

#### 与正向规则的关系

- 本节与通用 R-* 表冲突时以本节为准。例如 `R-OTHER:typo` 只用于**标识符**拼写，
  不用于注释 / docstring 文案；`R-OTHER:stale_comment` 仅在会误导时保留；
- **安全类规则键（`R-SHELL` 命令注入，以及兜底里的明文凭据 / SQL 注入 / 越权 /
  路径穿越 / 不安全反序列化 / 弱哈希 / 敏感信息外泄）在本场景不产出 suggestion** ——
  命中「安全类」不报清单即丢弃，连 `summary_md` 都不写；
- 仓库自定义规则优先于本节（见「强制例外」）；
- 不确定是否「有影响」时：**不报**。漏报可由后续轮次或人工补；误报会稀释真正的问题。
